## 3. Points forts

1. **Sécurité applicative solide** : helmet, argon2 pour les mots de passe, validation Zod systématique, RBAC testé (tests d'intégration dédiés), limitation IP en place.
2. **Hygiène TypeScript excellente** : un seul `as any` dans tout le dépôt (`backend/src/lib/prisma.ts:54`, justifié par commentaire — signature interne Prisma). Zéro `@ts-ignore`.
3. **Discipline architecturale** : séparation route → service → Prisma respectée, audit journalisé dans la transaction, soft delete, machine à états testée.
4. **Dépendances saines** : aucune vulnérabilité connue côté production sur les deux paquets.
5. **CI présente** (GitHub Actions) avec seed Postgres avant Vitest.
6. **Conventions tenues** : nommage français cohérent, argent en `Decimal`, dates en `DateTime`.

## 4. Problèmes détectés

### 🔴 P1 — Typecheck frontend en échec
```
src/components/DashboardOverview.tsx(3,92): TS7016 — pas de déclaration pour 'recharts'
src/components/DashboardOverview.tsx(485,33): TS7006 — paramètre 'val' implicite any
```
Le build Vite passe car il ne typecheck pas, mais la règle « TypeScript strict » du projet est violée. **Correctif :** `npm i -D @types/recharts` (ou vérifier la version installée — recharts ≥ 2 embarque normalement ses types) puis typer explicitement le paramètre `val` ligne 485.

### 🟠 P2 — Travail non commité
6 fichiers modifiés + un répertoire non suivi (`frontend/src/components/assignments/`). Risque de perte ou de divergence. À committer ou écarter après revue.

### 🟡 P3 — 4 `console.log` résiduels dans le backend
Remplacer par le logger structuré (`lib/journal-serveur.ts`) déjà présent.

### 🟡 P4 — Taille du bundle frontend
Plusieurs chunks lourds : `jspdf.es.min` 391 kB, `DashboardOverview` 386 kB, `html2canvas` 202 kB. Le jsPDF est déjà en import dynamique ; envisager le même traitement pour html2canvas et le découpage de Dashboard.

### 🟢 P5 — Menus
Logs de dev serveur (`dev-servers*.log`, `server-35.log`) traînent à la racine et dans `backend/`. Les ajouter au `.gitignore` ou les archiver dans `_sauvegardes/`.

## 5. Recommandations prioritaires

1. **Corriger les 2 erreurs TS du frontend** (P1) — bloque la règle « tsc --noEmit passe » du projet.
2. **Nettoyer et committer** le travail en cours (P2).
3. Remplacer les `console.log` par le logger maison (P3).
4. Ajouter une étape `typecheck` frontend au workflow CI pour éviter la régression (le CI actuel ne semble pas la détecter).
5. Différer les optimisations bundle (P4) après la stabilisation fonctionnelle.

## 6. Verdict global

**Projet en bonne santé.** Architecture respectée, tests nombreux et verts, zéro vulnérabilité de dépendance, secrets maîtrisés. Le seul vrai défaut est le typecheck frontend en échec (2 erreurs faciles à corriger) et du travail non commité à sécuriser.
